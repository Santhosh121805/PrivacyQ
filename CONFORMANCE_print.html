Project: Privacy-Preserving Adolescent Mental Health Using Quantum AI (DP-FedQ)
Status as of: 12 November 2026

This document states, for every box of the architecture diagram ("Quantum AI for Mental Health", boxes 1–15),
what the repository implements. A sub-item is BUILT only if code exists, has been run on the real data, and
has a test or a results file behind it.

StatusMeaning
BUILTImplemented and exercised; evidence listed.
PARTIALImplemented in a narrower form than the diagram names; the note says exactly how.
PHASE-2Not implemented; the note gives the reason.

Paths are relative to the repository root. results/ is produced by the commands in README.md; the run
directories are listed in configs/final_report.yaml. The quantum circuits are a representation layer only:
privacy comes from DP-SGD, federated learning, secure aggregation and the input-stage mechanisms, never from the
quantum computation.

Significance policy (all experiments). Comparisons are paired over the same cross-validation folds. Primary
test: Nadeau–Bengio corrected resampled t-test, Holm-adjusted within each pre-declared family; "significant" means
Holm-adjusted p < 0.05. The Wilcoxon signed-rank test, Holm-adjusted in the same families, is reported as a
sensitivity check. Rationale: top of results/RESULTS.md. Every comparison with both p-values:
results/significance/audit.csv and results/significance/changed.md.

Pipeline flow as built

NSCH 2024 survey → cleaning, identifier removal, train/test split →
[input-stage privacy: k-anonymity (k = 5) on quasi-identifiers] → imputation and one-hot encoding →
feature reduction (PCA, mutual information, UMAP or autoencoder) → [input-stage privacy: local DP on the encoder
input, ε_input] → quantum encoding → model (QSVM, VQC, hybrid QNN, or classical baselines) →
[training-stage privacy: DP-SGD (ε_training, Opacus), FedAvg, optional secure aggregation] → evaluation
(cross-validation and a locked hold-out) → report.

Box 4: Privacy-preserving mechanisms

Sub-itemStatusEvidenceNote
Differential privacy (training, DP-SGD)BUILTsrc/m7_privacy/dp_training.py, src/m7_privacy/accounting.py, tests/test_phase4_dp.py, Experiment 3Opacus DP-SGD; ε read only from Opacus's RDP accountant.
Federated simulationBUILTsrc/m6_federated/fedavg.py, tests/test_phase5_federated.py, Experiment 4FedAvg with 3, 5 and 10 clients, IID and split by U.S. state, client-side DP-SGD.
Secure aggregationBUILTsrc/m7_privacy/secure_aggregation.py, src/m6_federated/fedavg.py (secure_aggregation=True), tests/test_secure_aggregation.py (13 tests), configs/exp7b_secure_aggregation_nsch2024.yaml, results/exp7b-nsch2024-federated-secure-aggregation-20261112-153004/, scripts/secagg_overhead.py, results/secagg_overhead/overhead.mdPairwise additive masking (the masking core of Bonawitz et al., 2017): 2048-bit MODP Diffie–Hellman (RFC 3526 group 14, checked against the RFC's closed form) and SHA-256 / SHAKE-256 per-round masks. Updates are encoded as fixed-point integers (24 fractional bits) and masked and summed modulo 2⁶⁴, so the masks cancel exactly (tested bit for bit); client sizes are masked too. Each masked vector is computationally indistinguishable from random to the server (checked statistically by tests); a server colluding with 3 of 5 clients recovers only the 2 honest clients' sum. Overflow: negative values round-trip exactly in two's complement; each client refuses entries above a declared public bound, and setup refuses any configuration whose worst-case sum comes within 8 bits of 2⁶³. Worst case measured in Experiment 7c (10 clients, 3,786-row client, largest weight 8.94): 20.6 bits of headroom. Experiment 7b (Experiment 7 with secure aggregation): every stored metric identical to Experiment 7 in 30 of 30 runs. Cost: one-off key setup 0.5 / 1.5 / 6.1 s for 3 / 5 / 10 clients; masking 0.10–0.16 ms per client per round. Not implemented: client-dropout recovery, public-key authentication (honest-but-curious server only), defence against malicious clients. Secure aggregation is not differential privacy; the formal guarantee remains DP-SGD.
Homomorphic encryptionPHASE-2—Computationally impractical at this scale; a toy version would misrepresent its cost.
Privacy risk analysis (membership inference test)BUILTsrc/m9_audit/membership.py, tests/test_membership.py, src/m10_exp/exp6_membership.py, results/exp6-nsch2024-membership-inference-20261112-120934/Loss-threshold attack, 5 folds; results in box 12.
Input-stage privacy: k-anonymityBUILTsrc/m7_privacy/input_privacy.py, tests/test_input_privacy.py, results/exp5-nsch2024-input-privacy-20261112-120542/Experiment 5 only. k = 5 achieved on every fold's training rows; suppresses 13.0 % of rows on full data and 43.5 % on 1,200-row subsamples.
